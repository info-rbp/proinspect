## Reconciliation rules

1. **Do not merge every old Git branch into main.** Old V2, V3, V4, rental, marketing, reports, Calendar and finance branches include implementations superseded by later merged work and use older, conflicting migration numbering. Wholesale merges can revert newer source or mutate historical schema.
2. Merge only reviewed, current-source pull requests; record a verified exact-head CI run and the resulting main commit.
3. For a branch with a merged PR, retain the branch for audit; do not replay divergent old commits.
4. For closed/unmerged or unassociated historical branches, catalogue unique *requirements*, source files and tests under G03/O09–O11 and the corresponding F01–F20 packages. Reintroduce only verified missing feature slices in a new additive PR; do not imply full parity from branch ancestry or matching file paths.
5. Complete resolution of every previously approved historical feature still requires owner-approved scope and task-specific independent evidence. No missing owner/approval is invented.
