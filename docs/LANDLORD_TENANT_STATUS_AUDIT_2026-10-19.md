# Landlord and Tenant completion audit — 19 October 2026

**Audit baseline:** `main` at `965ea40bd333cfcbb47cb4037a94a506c68d0e71` (PR #27 merged during review).
**Scope:** Residential Landlord, Tenant, authorised Property Manager and Staff workflows; Commercial Landlord boundaries considered only where shared infrastructure or approvals could leak across sectors.
**Purpose:** Reconcile the seven outstanding capabilities from the October Landlord/Tenant functionality review against actual `main`, current development branches, draft PRs and open acceptance issues.
**This branch:** documentation and delivery coordination only. No application routes, D1 migrations, Cloudflare configuration, live users, bookings, Work Orders or legal notices are changed.

## How to read the statuses

- **Live code / deployed baseline:** implemented on `main`; hosted/provider acceptance still requires separate evidence. The last previously completed `main` verification at the start of the audit was [run 39031209818](https://github.com/info-rbp/proinspect/actions/runs/39031209818). The new PR #27 merge initiated a separate run and its final result must be checked before treating that SHA as release-verified.
- **Branch implemented — draft:** source and tests exist on a non-merged branch. Passing isolated CI is *not* a deployed, legally approved, government-integrated or externally accepted capability.
- **Partial:** some reusable code and data model exist, but the requested end-to-end user workflow cannot yet be completed safely.
- **Not implemented:** no complete supporting module found during this repository review. A schema/table alone does not imply UI, service or production functionality.
- **Release blocked:** evidence, legal/operational approval, migration reconciliation, production acceptance or security control required before merging.

## Existing source-of-truth architecture (protect in all delivery PRs)

1. One canonical user, client, property, tenancy and Staff model; effective-dated memberships and server-scoped access (`packages/authorization/server.ts`; `docs/DOMAIN_MODEL.md`).
2. Active all-inclusive customer subscription and sector-scoped service booking on `main` (migrations through `0006_all_inclusive_subscription.sql`); bookings and Work Orders are separate canonical records (`packages/authorization/subscription-booking.ts`; `apps/platform/worker/features/bookings.server.ts`).
3. Private R2, per-recipient grants, immutable issued PDFs, manual attachment quarantine and separate restricted evidence (`apps/platform/worker/features/documents.server.ts`).
4. Tenant invitations, active/past tenancy view, maintenance submissions, comments, published inspection references, PCR responses, reviewed-form intake and bond reference field (`apps/platform/worker/features/tenancies.server.ts`; `apps/platform/worker/features/forms.server.ts`).
5. Operations payment ledger and Stripe adapter record *service* charges, **not rent** or bond custody (`apps/platform/worker/features/finance.server.ts`; `docs/BUILD_STATUS.md`).
6. Staff manual report PDF issue and signed Report Tool handoff/callback are working code pathways, **not** the integrated native Report Builder (`apps/platform/worker/services.server.ts`; `apps/platform/worker/features/integrations.server.ts`).
