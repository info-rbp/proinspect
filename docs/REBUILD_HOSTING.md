# ProInspect Rebuild — temporary Cloudflare hosting

The owner authorised reuse of existing ProInspect infrastructure for live hosted development pending migration to Google Cloud. The dedicated Worker proinspect-rebuild deploys from proinspect-rebuild only. GitHub Actions uses the existing repository Cloudflare deployment secret; the initial Workers Builds token was rejected by the service.

Existing V3 staging D1 (all 67 migrations already applied as of 28 November 2026), R2 buckets, scanner service and scheduler are shared; no production resource is bound. The two dedicated rebuild event queues are used. Cron, real email, live payments, calendar writes and other release-gated functions are off by default. Do not concurrently exercise the old staging host against this shared test dataset while testing rebuild writes. Use synthetic accounts/records only. An independent rebuild DATA_ENCRYPTION_KEY is present; existing ciphertext from the earlier staging host may not decrypt with it. Do not modify old encrypted records or assume keys are interchangeable. The public marketing website and ProInspect sign-in/sign-up pages are accessible without Cloudflare Access. Only /auth/staging is protected by Access using the same three nominated staging testers; the application verifies its distinct Access audience before issuing a session. Workspace authorisation remains mandatory; public pages carry noindex headers. Live sign-in email remains disabled: testers use Continue with staging email from the ProInspect sign-in page. The build temporarily flattens only the rebuild configuration to prevent local Durable Object migration inheritance. No new migration is executed automatically: review and apply only compatible, explicitly approved changes to staging before exercising code that requires them.

The production main branch, connected environment, V3 staging Worker and production domains remain unchanged. Before final merge, remove temporary deployment-specific changes that are not part of production, verify migration compatibility, and obtain separate acceptance. Google Cloud migration is a future project, not part of this deployment.
